# qschema

Библиотека на Go для дискретно-тактового моделирования систем массового обслуживания. Схема состоит из источников заявок, каналов обслуживания, накопителей и блокираторов, которые направляют заявки по веткам.

## Требования и установка

Требуется Go 1.26 или новее.

```bash
go get github.com/NovikovRoman/qschema
```

## Быстрый старт

```go
package main

import (
 "fmt"
 "log"

 "github.com/NovikovRoman/qschema"
)

func main() {
 // Канал обрабатывает заявку два тика; nil означает конец схемы.
 channel := qschema.NewChannel("К1", 2, nil)

 // Источник создает заявку каждые три тика.
 source := qschema.NewSource("И1", 3, channel)
 schema := qschema.New(source)

 if err := schema.Run(10); err != nil {
  log.Fatal(err)
 }
 fmt.Println(schema.Report())
}
```

В `qschema.New` передаются начальные элементы схемы. Остальные элементы связываются через получателей: при обработке тика начальный элемент передает управление дальше по схеме.

## Элементы схемы

- **`Order`** заявка с идентификатором `ID`. Источник создает идентификаторы в формате `имя:номер`.
- **`Source`** создает заявки с заданным интервалом. Первая заявка создается на первом тике; получатель обязателен. Источник не проверяет готовность получателя перед передачей, поэтому для выбора свободного маршрута можно использовать `Blockers`.
- **`Channel`** одновременно обрабатывает одну заявку в течение заданного количества тиков. Готовая заявка передается получателю. Если получатель равен `nil`, заявка покидает схему.
- **`Storage`** накопитель с FIFO-очередью заданной емкости. За один тик он может передать не более одной заявки. При нулевой емкости возможна только непосредственная передача; при недопустимой емкости `Tick` вернет ошибку. Получатель `nil` означает конец схемы.
- **`Blocker`** отдельная ветка с условием и получателем. Условие получает заявку и порядковый номер заявки в системе блокираторов; `nil` вместо условия означает, что ветка подходит для любой заявки. Получатель `nil` завершает маршрут заявки.
- **`Blockers`** выбирает первую ветку, условие которой выполнено и получатель которой готов принять заявку. Всем веткам также передаются тики, в том числе без заявки. Если подходящей ветки нет, возвращается ошибка с `ErrBlockingScheme`.

Для обнаружения блокировки используйте `errors.Is`:

```go
if err := schema.Run(10); err != nil {
 if errors.Is(err, qschema.ErrBlockingScheme) {
  // Обработать блокировку схемы.
 }
 return err
}
```

Для этого фрагмента необходимы импорты `errors` и `github.com/NovikovRoman/qschema`.

### Маршрутизация

```go
fast := qschema.NewChannel("быстрый", 2, nil)
slow := qschema.NewChannel("медленный", 4, nil)

routes := qschema.NewBlockers("маршруты",
 qschema.NewBlocker("четные", func(_ *qschema.Order, n int) bool {
  return n%2 == 0
 }, fast),
 qschema.NewBlocker("остальные", nil, slow),
 // Если ни один канал не готов, заявка покидает схему.
 qschema.NewBlocker("отказ", nil, nil),
)
source := qschema.NewSource("источник", 1, routes)
schema := qschema.New(source)
```

`Blockers.CanAccept` сообщает только о наличии веток, не гарантируя готовность их получателей. При фактической передаче условия и доступность получателей проверяются в порядке веток.

## Запуск и отчет

`schema.Run(n)` выполняет `n` следующих тиков. Повторные вызовы продолжают нумерацию: например, `Run(5)` и еще один `Run(5)` обрабатывают тики с 1 по 10. Если элемент вернул ошибку, выполнение останавливается; частично обработанный тик при следующем вызове не повторяется. Операции элементов при ошибке не являются общей транзакцией и не откатываются автоматически.

`schema.Report()` возвращает текстовый отчет о состоянии элементов. Если несколько веток ссылаются на один накопитель или канал, отчет этого общего объекта будет повторен в каждой ветке; это не отдельные счетчики.
